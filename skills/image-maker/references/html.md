# HTML の書き方とチェック

案を作るとき（手順 4・6）に読む。

## HTML の書き方

- 1 案 1 ファイル。`<html lang="ja">` にする（ないと日本語の改行や字形がおかしくなる）。`html, body` を spec の幅と高さに固定し、`overflow: hidden` にする。
- フォントは Google Fonts を `<link>` で読み込み、`display=block` を付ける。`swap` だと、読み込み前の代わりのフォントのまま撮影されることがある。ローカルの日本語フォントは環境によって違うので頼らない。
- 写真は `assets/` を相対パスで参照する。
- `texts.json` のテキストを入れた要素には `data-text="<id>"` を付ける（例: `<p data-text="date">発売日 <b>◯月◯日</b></p>`）。1 つのテキストを複数の要素に分けるときは、それぞれに同じ `id` を付ける。「写真」と書いた仮の枠など、文章ではない文字には `data-placeholder` を付ける。
- `rephrase` で言い換えたときは、`notes.md` にその案の言葉を書く。
- 文字はセーフエリア（spec の `safe`）の内側に置く。背景や写真ははみ出してよい。

## 日本語の改行

- 見出しの改行は `<br>` で自分で決める。長い本文は `word-break: auto-phrase` を使う（`lang="ja"` がないと効かない）。
- `<br>` を入れたら、各行をそれだけで読んで意味のまとまりになっているか確かめる。「はじめ／ました。」は ×、「新作、／はじまりました。」は ○。自分で入れた改行の誤りは、自動では見つけられない。
- 1 行が幅に収まらないときは、改行位置をずらしてごまかさず、文字を小さくするか言葉を短くする。

## チェック

`render.mjs` が問題を見つけると、種類ごとに直し方を表示する。見せる前に直して撮り直す。わざとそうしている場合は、次の属性で警告を止められる。

| 属性 | 使う場面 |
| --- | --- |
| `data-outside-safe-ok` | 端に置く飾り文字 |
| `data-small-ok` | 小さくてよい注記 |
| `data-wrap-ok` | 自動の折り返しに任せてよい見出し |

`priority-inverted`（優先順位の低いテキストのほうが大きい）は、文字の大きさだけで判定している。色や位置で優先順位を表しているなら問題ない。

そのあと `sheet.png` を自分で開き、自動では見つけられない点を目で確かめる:

- 不自然な改行、行頭の句読点
- 背景と文字の色が近くて読みにくい
- 縮小した大きさで、優先順位 1 のテキストが最初に目に入るか
- 8 案が十分に違っているか（1 回目）
