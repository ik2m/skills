# 載せる文章を決める（texts.json）

手順 2 で読む。

## 決め方

1. 聞き取った内容から、載せるテキストを 1 つずつ書き出す。
2. それぞれに、変えてよいかと優先順位を仮に付ける。目安:

   | テキストの種類 | 変えてよいか | 理由 |
   | --- | --- | --- |
   | 日付・価格・数値・店名・商品名・電話番号・URL | `fixed` | 1 文字違うだけで誤りになる |
   | 案内・補足（「詳しくはプロフィールのリンクから」など） | `shorten` | 狭い配置では縮めたいが、意味は変えたくない |
   | キャッチコピー・見出し | `rephrase` | 言葉の切り口も案の違いになる |

3. 表にしてユーザーに見せる。次の 2 つはユーザーが決めることなので、質問ツール（Claude Code なら `AskUserQuestion`）で 1 回にまとめて聞く。選択肢はテキストそのもの（4 つまで。それ以外は「その他」で答えてもらう）。質問ツールがなければ、番号付きの選択肢を文章で示す。
   - 「いちばん最初に見てほしいのはどれですか？」（1 つ選択。仮の優先順位 1 を先頭に置き、`(おすすめ)` と付ける）
   - 「削ったり言い換えたりしてはいけないものはどれですか？」（複数選択。`rephrase` と `shorten` にしたテキストを選択肢にする）

優先順位 1 は 1〜2 個にする。全部が 1 だと、どれも目立たない。「全部大事」と言われたら、「スマホで一瞬だけ見た人に、1 つだけ伝わるとしたらどれですか」と聞く。

キャッチコピーの言い回しは提案してよいが、事実を足さない。`texts.json` にない文字が画像に載ると、変換スクリプトが知らせる。

## 書式

```json
{
  "texts": [
    { "id": "headline", "text": "焼きたてを、朝いちばんに。", "priority": 1, "edit": "rephrase" },
    { "id": "date",     "text": "発売日 ◯月◯日",             "priority": 2, "edit": "fixed" },
    { "id": "cta",      "text": "詳しくはプロフィールのリンクから", "priority": 3, "edit": "shorten" },
    { "id": "name",     "text": "（店名）",                   "priority": 3, "edit": "fixed" },
    { "id": "status",   "text": "数量限定",                   "priority": 4, "edit": "fixed", "optional": true }
  ]
}
```

| 項目 | 意味 |
| --- | --- |
| `id` | HTML の `data-text` で参照する名前（英数字） |
| `text` | 載せる文章。改行と空白は比べるときに無視されるので、改行位置はデザイン側で決めてよい |
| `priority` | 視線を集める順番。1 が最初に目に入るもの。同じ数字も可 |
| `edit` | `fixed`: 一字一句そのまま／`shorten`: 文字を削るのは可、足す・変える・並べ替えるのは不可／`rephrase`: 意味が同じなら言い換え可 |
| `optional` | `true` なら載せなくてもよい。省略すると必須 |

`texts.json` は `spec.json` と同じフォルダに置くと、`render.mjs` が自動で読む（別の場所なら `--texts <file>`）。

## 途中で文章が変わったとき

「この言葉がいい」「日付を入れたい」と言われたら、先に `texts.json` を直してから HTML を直す。言い換えた見出しが気に入られたら、その言葉に書き換えて `fixed` にする。以降の案で、気に入られた言葉が勝手に変わらないようにするため。
