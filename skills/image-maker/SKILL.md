# image-maker

HTML/CSS で画像を組み、`scripts/render.mjs`（Playwright）で PNG にする。デザインは言葉で詰めるより、並べて見て選ぶほうが早く決まる。だから「8 案を見せる → 選んでもらう → 8 案を作り直す」を確定までくり返す。

## 原則

- **事実は作らない。** 日付・価格・数値・店名など確かめられる事柄は、ユーザーから受け取ったものだけを載せる。
- **素材を勝手に埋めない。** 写真がなければ、ネットの画像や生成画像を使わず「写真」と書いた枠を置く（権利がわからないため）。
- **媒体の数値を思い込まない。** サイズやセーフエリアは投稿先ごとに違い、仕様も変わる。ユーザーに聞くか、その時点の仕様を調べる。

## 流れ

### 1. 聞き取り

足りないものだけを、まとめて 1 回で聞く: 用途と見る人／載せる文字／素材（写真・ロゴ）／投稿先とサイズ／雰囲気や決まりごと（「おまかせ」も可）。

### 2. 載せる文章を決める

デザインに入る前に、テキストごとに「文章」「変えてよいか（`fixed` / `shorten` / `rephrase`）」「視線の優先順位」を決めて `texts.json` に書き、表にしてユーザーに確かめる。案ごとに文章が勝手に変わるのを防ぎ、変換スクリプトで全案を機械的に突き合わせるため。決め方と書式は `references/texts.md`。

### 3. 作業フォルダを作る

指定がなければ作業ディレクトリの下に作る。毎回の HTML を残すのは、「1 回目の 4 に戻したい」に応えるため。

```
image-work/<YYYYMMDD>-<短い名前>/
  brief.md     聞き取りと、各回のフィードバック（ユーザーの言葉のまま）
  texts.json   載せる文章
  spec.json    {"width":1080,"height":1350,"safe":{"top":60,"right":60,"bottom":60,"left":60},"minFontPx":28,"previewWidth":300}
  assets/      ユーザーから受け取った写真・ロゴ
  round-1/     1.html … 8.html、notes.md（各案のねらい 1 行）
  final/
```

`spec.json` は `width` / `height` だけが必須。`safe` は文字を置かない端の幅、`minFontPx` はこれより小さい文字を警告する大きさ、`previewWidth` は一覧での 1 案の幅（実際に見られる大きさに近づける）。

### 4. 1 回目: 方向性を大きく変えた 8 案

目的はユーザーが好きな方向を見つけること。配置・書体・色・言葉の切り口（`rephrase` のテキストだけ）・優先順位 1 の目立たせ方を組み合わせ、8 案がそれぞれ違う方向になるようにする。引き出しは `references/design-tips.md`、HTML の書き方とチェックの手順は `references/html.md`。

```bash
node <この Skill のパス>/scripts/render.mjs --spec image-work/<名前>/spec.json --in image-work/<名前>/round-1
```

各案の PNG と、8 案を番号付きで並べた `round-1/sheet.png` ができる。見せる前に、スクリプトが出した問題を直して撮り直し、`sheet.png` を自分で開いて目でも確かめる。壊れた案はユーザーの選ぶ手間を無駄にするため。

### 5. 見せて、選んでもらう

`sheet.png` を見せ（ファイルを送る道具があれば画像で）、各案のねらいを 1 行ずつ添えて、**気になる番号と、その案の何が良かったか**を聞く。選ばなかった案で「これは違う」と思ったものも聞く。案は「回-番号」（`1-3`、`2-5`）で呼ぶ。

理由まで聞くのは、良かった点を残したまま、それ以外を大胆に変えるため。理由がわからないと細部しか変えられず、似た案が並ぶ。番号だけの返事への聞き返し方と記録のしかたは `references/feedback.md`。

### 6. 2 回目以降: 良かった点は残し、まだ決まっていない観点を変えた 8 案

選ばれた案の HTML をコピーして土台にする（ゼロから書くと、気に入られた細部が消える）。「残す」ものは変えず、「避ける」ものは使わず、「まだわからない」観点を 1 案ごとに 1 つ、一覧で見分けられる量だけ変える。2〜3 案は少し外した案にする。

ほぼ決まっていれば 8 案を作らずに「決定にしますか」と聞き、細かい修正だけなら 1 案直して見せる。詳しくは `references/feedback.md`。

### 7. 仕上げ

1. 確定した案を `final/final.html` にコピーし、`render.mjs --in image-work/<名前>/final/final.html` で書き出す。投稿先が決めているピクセル数のままが基本で、ユーザーが高解像度を望むときだけ `--scale 2` を付ける。
2. 問題が 0 件であることと、PNG を原寸で開いて確かめる。
3. PNG を渡し、文字や日付を差し替えられるよう `final.html` の場所も伝える。
